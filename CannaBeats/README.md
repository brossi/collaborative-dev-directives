# CannaBeats (iOS)

A Hitster-style family music game for iOS: blind playback of
a shuffled, no-repeat song deck via Spotify, with pause/resume, a game-master
reveal, and manual advance. Plan and rationale:
[`../plans/hitster-family-edition--ios-mvp.md`](../plans/hitster-family-edition--ios-mvp.md).
Verified findings that shaped the current code:
[`docs/adversarial-review-2026-07-30.md`](docs/adversarial-review-2026-07-30.md).

## Layout

```
CannaBeats.xcodeproj/       Xcode 16 project (folder-synced — files added on
                            disk appear in Xcode automatically)
Config/Info.plist           URL scheme for Spotify auth callback +
                            LSApplicationQueriesSchemes (merged into the
                            generated Info.plist at build time)
CannaBeats/
  CannaBeatsApp.swift       App entry; routes auth callback + scene phase
  Models/Song.swift         One catalog row (title/artist/year/genres/uri)
  Models/Catalog.swift      Module discovery, dedupe, CatalogFilter (year/genre)
  Models/GameSession.swift  Shuffled no-repeat deck, built from a filter
  Playback/PlayerModel.swift    UI-facing facade + reconnect-before-action guard
  Playback/StubBackend.swift    Fake player (logs) — used in the simulator
                            always, and anywhere SpotifyiOS is absent
  Playback/SpotifyBackend.swift Real App Remote backend + cover art via imageAPI
  Playback/SpotifyConfig.swift  ← paste your Client ID here (or use the
                            gitignored Resources/SpotifyClientID.txt)
  Views/GameView.swift      The one screen (connect / hidden song / reveal)
  Views/RevealCard.swift    Cover art / title / artist / big year
  Resources/Catalog/        BUILD PRODUCT — bundled packs, regenerated by
                            `tools/status.py --sync`. Do not hand-edit.
Frameworks/                 SpotifyiOS.xcframework — linked + embedded by the
                            project, but GITIGNORED: a fresh clone must
                            re-download it (Stage B below)
catalog/years/              SOURCE OF TRUTH: top ~30 US hits per year 1920-2026
catalog/themes/             SOURCE OF TRUTH: theme packs (film/TV/Tony/Oscar)
tools/status.py             Coverage table + source→bundle sync (no network)
tools/fill_from_datasets.py Offline URI fill from dataset mappings (no quota)
tools/csv_to_mappings.py    Any CSV with Spotify IDs → mapping rows
tools/playlists_to_mappings.py  Spotify playlists → mapping rows (~100
                            tracks per API request — the cheap API path)
tools/verify_uris.py        oEmbed URI checker (no credentials, no quota)
tools/resolve_uris.py       Per-song Spotify search (1+ request per song —
                            the EXPENSIVE path; budgeted, use last)
tools/playlist_to_songs.py  Playlist → new module rows (alt. sourcing)
tools/_common.py            Shared norm/token/API plumbing
```

**The two-directory rule:** `catalog/` is the single source of truth; the
tools read and write it. `Resources/Catalog/` is what the app bundles and is
a build product — regenerate it with `python3 tools/status.py --sync` after
any catalog change, then rebuild the app. Never edit the bundle copies.

**Run every tool from this directory** (`CannaBeats/`, the folder containing
`catalog/` and `tools/`). `status.py` works from anywhere; the others assume
this cwd for their relative paths.

## Getting it running

**Stage A — game loop only (no Spotify needed, works in the simulator):**

1. Open `CannaBeats.xcodeproj` in **Xcode 16 or newer** (the project uses
   folder-synced groups). Set your signing team under
   Signing & Capabilities.
2. Run. In the simulator the app always uses the **stub player** (orange
   banner) — App Remote needs the Spotify app, which the simulator doesn't
   have, so `PlayerModel` requires `!targetEnvironment(simulator)` before
   selecting the real backend. The whole game loop — Connect → Next Song →
   pause/play → Reveal → Next — works, logging playback instead of making
   sound. Adding the framework does *not* change this; only a real device does.

*Fallback if the project file won't open:* create a fresh iOS App project named
`CannaBeats` in Xcode, delete its template sources, drag the `CannaBeats/`
source folder in, and add the two keys from `Config/Info.plist` to the target's
Info tab. ~2 minutes.

**Stage B — real audio (device + Spotify app + Premium):**

1. At [developer.spotify.com/dashboard](https://developer.spotify.com/dashboard)
   create an app. Add Redirect URI `cannabeats://spotify-callback` and, under
   iOS settings, the bundle ID `social.cannabeats.app` (or whatever you
   changed it to). Development mode is fine — but it only authorizes accounts
   explicitly added to the app's user list. If the Spotify app on the phone is
   signed into an account that isn't on that list, auth is refused with the
   unhelpful message "An unknown error has occured". Two client IDs from
   different accounts are easy to mix up here; the ID you bundle must belong
   to the app whose user list includes the phone's account.
2. Provide the Client ID either by pasting it into
   `Playback/SpotifyConfig.swift`, or — to keep it out of git — by writing it
   to the gitignored file `CannaBeats/Resources/SpotifyClientID.txt` (just the
   ID, nothing else; it's bundled and overrides the constant). The app
   refuses to connect with the placeholder ID and says so on screen.
3. Put `SpotifyiOS.xcframework` at `Frameworks/SpotifyiOS.xcframework`. The
   project already links and embeds it from that path — **no dragging into
   Xcode required** — but it's gitignored, so a fresh clone has to fetch it:

   ```sh
   curl -sL -o /tmp/sdk.zip https://github.com/spotify/ios-sdk/archive/refs/tags/v5.0.1.zip
   unzip -q /tmp/sdk.zip -d /tmp && cp -R /tmp/ios-sdk-5.0.1/SpotifyiOS.xcframework Frameworks/
   ```

   (The SDK ships the framework in the repo tree, not as a release asset.)
4. Run **on a real iPhone** with the Spotify app installed and logged in to
   Premium. App Remote cannot work in the simulator — there's no Spotify app
   to talk to — so the simulator stays on the stub even with the framework
   present.

If "Connect Spotify" fails, the on-screen error names its phase:
"Spotify auth refused" means the dashboard config or the signed-in account
(step 1); "App Remote connect failed" means auth worked and attaching to the
Spotify app didn't — check it's running, signed in, and Premium.

"Connect Spotify" bounces to the Spotify app, plays a short warm-up track
(paused automatically once linked), and returns. The bounce happens on the
first play of **each app launch** — after that, every song starts in the
background and the app never leaves the screen.

## The catalog (modular)

The catalog is a set of **module files** — any number of JSONs; the app
discovers, merges, and dedupes what's in `Resources/Catalog/` at launch.
A module is a per-year pack, a genre pack, a theme pack — same schema:

```json
{
  "module": "year-1985",
  "name": "Hits of 1985",
  "source": "Billboard Year-End Hot 100, 1985 (top 30)",
  "songs": [
    { "title": "…", "artist": "…", "year": 1985, "genres": ["pop"], "uri": "spotify:track:…" }
  ]
}
```

`CatalogFilter` (year range and/or genres) already narrows the deck at
session build; the future round-setup UI is just controls over that filter —
e.g. a 1990–2026 range so younger players get an even field, per round.

### Pipeline: fill offline first, spend quota last

Spotify development-mode apps have a **daily request quota** (~600–1000/day,
shared across every app on your developer account — see the repo CLAUDE.md).
The pipeline is ordered so the free steps do the bulk of the work:

1. **Fill from datasets — free.** Convert any dataset that maps songs to
   Spotify IDs into mapping rows, then fill the catalog offline:

   ```sh
   python3 tools/csv_to_mappings.py tracks.csv --title name --artist artists \
       --year release_date --id id > mappings/kaggle.jsonl
   python3 tools/fill_from_datasets.py --mappings mappings/*.jsonl -- \
       catalog/years/*.json catalog/themes/*.json
   ```

   (Check your CSV's real header first — dataset schemas drift.)

2. **Playlists — cheap.** A playlist read returns ~100 tracks per API
   request vs 1 request per song for search. Paste playlist links into a
   file and:

   ```sh
   python3 tools/playlists_to_mappings.py --from-file playlists.txt \
       --out mappings/playlists.jsonl
   python3 tools/fill_from_datasets.py --mappings mappings/playlists.jsonl -- \
       catalog/years/*.json catalog/themes/*.json
   ```

3. **Verify — free.** Checks every resolved URI against Spotify's public
   oEmbed endpoint (no credentials, no quota):

   ```sh
   python3 tools/verify_uris.py catalog/years/*.json catalog/themes/*.json
   ```

   Note: oEmbed proves a track **exists**, not that it's playable in your
   account's market. If the game account's country isn't the US, spot-check
   a few old tracks in the Spotify app (search was pinned to `market=US`).

4. **Resolve the residue — expensive.** Per-song search for whatever's
   still null. Credentials come from a gitignored `.env`
   (`cp .env.example .env`; the client secret lives ONLY there, never in
   the app). No US IP is needed — the search pins `market=US` itself.

   ```sh
   python3 tools/resolve_uris.py catalog/years/*.json catalog/themes/*.json \
       --out /tmp/resolved
   ```

   It stops itself at `--budget` (default 400) requests, saves progress on
   any interruption, and re-runs continue where it left off — source edits
   are always honored (output URIs are merged onto the current source).
   Failures are marked `"unresolved": true` and skipped on re-runs unless
   `--retry-unresolved`.

   Send `--out` to a scratch directory, **not** to `Resources/Catalog/`.
   Writing the bundle directly leaves the new URIs only in the build
   product, where the next `--sync` has to "rescue" them back and warns
   that a source edit may drop them. Instead let the resolver's track log
   carry them into source, which is where they belong:

   ```sh
   python3 tools/fill_from_datasets.py --mappings mappings/spotify-tracks.jsonl -- \
       catalog/years/*.json catalog/themes/*.json
   ```

   Every resolution also appends the whole chosen track to
   `mappings/spotify-tracks.jsonl` — artist IDs, ISRC, the lot. Nothing
   re-searches a song that already has a URI, so anything not captured
   there costs full quota to recover. That file is also what
   `tools/harvest_artist_ids.py` merges into the artist registry.

5. **Sync + bundle.** `python3 tools/status.py --sync`, rebuild the app in
   Xcode. `python3 tools/status.py` at any time shows coverage and
   source/bundle drift. If sync reports rescued URIs, step 4 was run
   against the bundle — back-fill them into `catalog/`.

- `year` is the **chart year**, hand-verified. Never trust Spotify album
  dates — remasters and compilations lie.

## Game-night notes

- The host phone holds the game; lock screen / Control Center will show the
  playing track title — host keeps the phone, same trust model as the boxed
  game.
- Long debates can suspend the Spotify app and drop the connection; the app
  reconnects on the next button press, re-bouncing through Spotify if it has
  to wake it. A "Skip song" button covers dead or region-blocked tracks
  without revealing the answer.
- Free Apple developer account sideloads expire after **7 days** — re-deploy
  from the Mac weekly while traveling.
